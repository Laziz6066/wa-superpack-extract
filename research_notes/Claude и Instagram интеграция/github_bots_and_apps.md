# GitHub census: Claude/Anthropic-powered Instagram bots and apps (not MCP servers, not Claude Code skills), as of late Oct 2026

Method: GitHub repository search through the GitHub MCP tool. Queries: "instagram claude", "instagram anthropic", "instagram ai agent dm", "n8n instagram claude", "instagram in:name topic:claude", "instagram influencer outreach claude OR anthropic", "instagram agent in:name stars:>150", and others. Code search: `"from anthropic import" instagrapi`, `"import anthropic" instagrapi`, `anthropic "graph.instagram.com"`. About 20 READMEs were downloaded from raw.githubusercontent.com and read. The direct REST API (`api.github.com/search`) returned 403 in this sandbox, so all star counts and dates come from the MCP search results taken on 2026-10-30. "Updated" means the repo's `updated_at` field, which also changes when someone stars the repo, so it can be more recent than the last commit. Licenses are listed only where the README states one. Otherwise the license is shown as "?".

Scope note: the top results for "instagram claude" are mostly Claude Code skills and MCP servers, which this census excludes. Examples are Jakeschincariol/instagram-agent-skill (~3.8k★), sergebulaev/instagram-skills (~670★), ScrapeCreators/social-media-research-skills (~5.1k★) and many `instagram-mcp` repos. Standalone apps and bots that call Claude are much less popular. Most have fewer than 100 stars and were created in 2026.

## Q1. Census: which repos exist (name/URL, stars, activity, language, function, LLM, IG access, license, maturity/risk)

### Takeaway
The standalone ecosystem is small and new: about 25 relevant repos, nearly all created between 2025 and 2026. They fall into six groups:
1. DM and comment auto-reply webhook bots on the official API
2. Self-hosted ManyChat-style comment-to-DM platforms
3. Autonomous content and auto-posting agents, often using unofficial instagrapi
4. Carousel and reel generators that use Claude or the Claude Code CLI as the "brain"
5. Analytics, competitor research and commerce agents
6. n8n workflow JSON repos

Only two repos with Claude as an option reach 200 or more stars: open-carrusel (~504★) and OpenReels (~226★). Neither of them posts to Instagram through an API.

### Inferences
- Claude is the default or recommended LLM in most of the DM, comment and content repos above, but the absolute numbers are tiny. Popularity sits with the skills and MCP formats, which are out of scope here. Standalone Claude-powered IG bots are mostly templates, agency lead magnets (Ootto, Forgemind, brodyautomates) or portfolio pieces.
- One emerging pattern skips paid API calls by using the Claude Code CLI as a subprocess (open-carrusel, reelsmith) or by having the user paste data into a chat (ig-reply).

## Q2. Which are most popular and maintained? Which use official APIs and which use risky unofficial ones?

### Takeaway
By stars, the leaders are open-carrusel (~504★) and OpenReels (~226★). Both are content generators that never authenticate to Instagram, so their ToS risk is low. Among repos that actually act on an account, the busiest are sunmughan/meta-automation (101★, browser CDP, high risk) and alsk1992/instagram-ai-agent (58★, instagrapi plus anti-detection, high risk, but the most engineered with 671 tests). The official-API DM and comment bots (ForgeGrowth-OSS, ig-setter, dm-engine, palych65, georgeding, Pranayseekgrowth) are the safer group, but they have fewer than 30 stars each.

### Inferences
- Official-API projects focus on Business and Creator accounts, DMs and comments, where Meta's APIs are solid. Unofficial projects focus on fully autonomous growth: follows, posting from personal accounts, warm-up. That goal pushes them toward instagrapi and anti-detection tricks.
- For a production recommendation, the official-API webhook bots are the safe templates. palych65 and georgeding are minimal. ForgeGrowth-OSS is the most feature-complete.

### Gaps
- No repo provided measured ban rates for instagrapi or CDP approaches. The risk claims rest on README self-disclosure, not data.
- Issue-tracker activity was not analysed, so maintainer responsiveness is unknown.

## Q3. Typical architectures and code patterns

### Takeaway
Five architectures recur:
- **(A) Webhook DM/comment bot:** a Meta webhook feeds a small server (Flask, FastAPI, Express, Cloudflare Worker or n8n), which calls Claude with a voice/brand file plus conversation memory and replies through the Graph or Messaging API. Guardrails include DRY_RUN, keyword triggers, human hand-off and Telegram mirroring.
- **(B) Polling comment-to-DM funnel:** private replies, email capture and a lead webhook.
- **(C) Scheduled content pipeline:** a cron or GitHub Actions job runs trend collection → Claude script or caption → image or video generation (Flux/LoRA, gpt-image, Remotion, Puppeteer HTML→PNG) → a human approval gate (Telegram, Airtable or a web `/review` page) → publish.
- **(D) Claude Code CLI as the engine** inside a local app (no API key).
- **(E) Scrape → Claude Vision analysis → report** for competitor or influencer research.

### Cited Findings
- (A) Flow: "Instagram DM → Meta webhook (HTTPS) → Flask app verifies + routes → keyword/engagement check → Claude drafts a reply in your voice (agent.py + style_guide.md) → reply sent via the Instagram API (+ Telegram mirror / ElevenLabs)", with per-conversation JSON memory in `state.py` — [palych65](https://github.com/palych65/claude-instagram-bot)
- (A) "Instagram DM / comment → Meta webhook → this server → Claude → Instagram Graph API → reply". It keeps the last 10 messages as context, hands pricing and complaints to a human, and defaults to `DRY_RUN=true` — [Pranayseekgrowth](https://github.com/Pusparaj99op/Pranayseekgrowth_Instagram_agent)
- (A, serverless) One Cloudflare Worker serves IG and WhatsApp. D1 stores history, the knowledge base, tickets and caps. Resend handles escalation. The model is `claude-sonnet-4-6` — [georgeding](https://github.com/georgeding/meta-social-ai-agent)
- (A, n8n + dashboard) "Instagram DM → Meta Webhook → n8n → Claude AI → Supabase → Dashboard; Override Send ← Dashboard → n8n → IG Reply" — [ig-setter](https://github.com/brodyautomates/ig-setter)
- (B) Comment keyword → DM with link → ask for email → follow-up nudge → `LEAD_WEBHOOK_URL`. The AI is told not to invent prices or follow instructions embedded in comments, and falls back to a canned reply. Runs as a macOS LaunchAgent — [dm-engine](https://github.com/machinedigital-ai/dm-engine)
- (C) "Cron (daily) → Flux + identity LoRA + style LoRA image, Claude caption → Telegram notification with approve/reject buttons → DB status + scheduled publish with anti-bot jitter" — [drlejeune](https://github.com/drlejeune/ai-instagram-content-pipeline)
- (C) Collectors → planners/strategy (Claude) → generators → poster, under an `InstagramAIAgent` orchestrator and scheduler — [PINKDIAMONDVVS](https://github.com/PINKDIAMONDVVS/ai-instagram-agent-pinkdiamondvvs)
- (C) Separate n8n workflows for generation, publishing, analytics and the token refresher (every 50 days). Airtable is the approval UI — [Kostia1001](https://github.com/Kostia1001/n8n-social-media-autopilot)
- (C) A GitHub Actions scheduled run with secrets, `auto-generate/config.yml` and a review gate by default — [Ootto autopilot](https://github.com/Ootto-AI/claude-instagram-autopilot)
- (D) The Claude CLI runs as a subprocess and Puppeteer exports PNGs. Claude writes HTML/CSS slides — [open-carrusel](https://github.com/Hainrixz/open-carrusel). ### Inferences
- Common code-level patterns:
  1. A "voice/style guide" Markdown file injected into the system prompt
  2. Keyword triggers that gate when the LLM is called
  3. Short rolling conversation memory (JSON, SQLite, D1, Supabase)
  4. Escalation or hand-off rules (pricing, complaints)
  5. DRY_RUN or approval gates before anything goes public
  6. Webhook signature verification (HMAC `X-Hub-Signature-256`) and a verify token
  7. Token refresh jobs for 60-day IG tokens
  8. Randomized delays and rate-limit backoff
  9. Treating user-generated text as untrusted against prompt injection
- Remotion (video) and Puppeteer/Playwright HTML→PNG (carousels) are the standard rendering layer for content generators. Image models come from other vendors (Flux, gpt-image, Gemini), since Claude does not generate images.
