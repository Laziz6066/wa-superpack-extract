# Unified-memory devices for local coding LLMs, budget about $2000 (as of 30 Oct 2026)

Research note: many retailer and review hosts (apple.com, tomshardware.com, computingforgeeks.com, hardware-corner.net, macpro-la.com, nordicsilicon.io) could not be fetched from this session (blocked by the network allowlist). Price figures below come from search-result snippets of those pages and are attributed to them, but I did not read the full pages. github.com pages did load and are the most reliable sources here. Several 2026 "guide" sites (promptquorum, openclawdc, betterclaw, millionminer and others) look like SEO aggregators, so I treat them as weak.

**Main finding for the buyer:** the 2025–2026 DRAM shortage has roughly doubled prices for 128 GB unified-memory boxes. In late October 2026, **no new 128 GB device (Strix Halo, DGX Spark/GB10 or Mac) costs $2000 or less.** At $2000 the realistic options are:
- a 64 GB Strix Halo, for example Framework Desktop 64GB at $1,959 (pre-order), GMKtec EVO-X2 64GB at $2,199 (a stretch), or a refurbished Framework 64GB at $1,659;
- a used M1 Max 64GB Mac Studio at about $1,650–2,000 sold;
- a Mac mini, but 64 GB versions start at about $2,999.

- Within $2000, a Strix Halo buyer gets **64 GB**. After the GPU split (about 48–56 GB usable for the GPU), that fits Qwen3-Coder-30B-A3B, gpt-oss-20b, Devstral-Small 24B and Qwen3.5/3.6-35B-A3B at Q4–Q8 with long context. ## 5. Practical issues: ROCm/Vulkan, Linux vs Windows, GPU memory allocation, noise and power

### Takeaway
On Linux, Strix Halo now works well with a kernel of 6.18.4 or newer and native gfx1151 support in ROCm 7.x. Set a small BIOS VRAM carve-out and raise the GTT/TTM limit to about 120 GB with kernel parameters. Vulkan (RADV) is usually best for generation and HIP for prefill. Ollama lags well behind current llama.cpp.

### Cited Findings
- By default the GTT limit is about 50% of RAM. AMD recommends a small dedicated BIOS VRAM reservation (for example 0.5 GB) and raising the shared TTM/GTT limit instead. — [AMD ROCm docs: Strix Halo optimization](https://rocm.docs.amd.com/en/latest/how-to/system-optimization/strixhalo.html)
- To get about 120 GiB for the GPU, set `ttm.pages_limit=31457280 ttm.page_pool_size=31457280` (counted in 4 KiB pages). The two values must match. The default ceiling is about 62 GB. — [search summary of setup guides](https://github.com/burrellka/MyStrixHaloSetup)
- The required kernel patches are upstream in Linux 6.18.4 and newer. One user reported that the amd-ttm tool setting did not survive a reboot, while the kernel command line worked. mmap above 64 GB was very slow due to a ROCm issue, so people use `--no-mmap`. — [Level1Techs thread](https://forum.level1techs.com/t/rocm-can-only-use-half-of-the-unified-memory-on-my-strix-halo/253152), [AMD ROCm docs](https://rocm.docs.amd.com/en/docs-7.2.0/how-to/system-optimization/strixhalo.html)
- Older ROCm builds needed `HSA_OVERRIDE_GFX_VERSION=11.5.1`. Current native gfx1151 builds should not. Vulkan gives better generation and HIP better prefill (for example Qwen3-Next: HIP pp512 800 vs Vulkan 752; Vulkan tg 59 vs HIP 50). — [strix-halo-guide](https://github.com/hogeheer499-commits/strix-halo-guide/blob/main/BENCHMARKS.md)
- Ready-made toolbox containers exist (kyuz0) for vLLM and ComfyUI on Strix Halo. — [kyuz0 toolboxes](https://github.com/kyuz0/amd-strix-halo-comfyui-toolboxes)

### Inferences
- For a 64 GB unit, a 48–56 GB GPU allocation through GTT is realistic, leaving 8–16 GB for the OS and IDE.
- Windows works through LM Studio/Vulkan with a fixed BIOS split (for example 48/16). Linux is preferred for flexible GTT and up-to-date llama.cpp. This is general community practice, not specifically cited here.

### Gaps
- No noise (dB) or wall-power measurements were retrieved; the Tom's Hardware and Phoronix pages were not reachable. Commonly reported figures are about 120–140 W package power under load for 395 mini PCs, but this is not verified here.
- International availability for Uzbekistan/CIS was not researched in depth. GMKtec, Bosgame and Minisforum ship worldwide from China/HK via their own stores and AliExpress. The Framework Desktop ships only to supported countries (Uzbekistan is not known to be one, unverified). Apple and NVIDIA have no official Uzbekistan store. All of these are unverified assumptions.
